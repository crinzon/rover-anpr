# Проверка номера в /live

Обычный запуск API и Front/Back сохранён. После изменения Python-файлов перезапустите API
и процессы камер, затем обновите http://localhost:8000/live.
`.env`, адреса камер, пароли и модели не меняются. База данных берётся из существующего DB_PATH,
либо plates.db по умолчанию; новый реестр для этой функции не требуется.

Над каждым видео — последний номер по накопленной штатной логике, ниже — фактический OCR
этого кадра, статус и вырезка из исходного изображения. Это разные значения: OCR может меняться,
пока накопленный номер остаётся PARTIAL. При нескольких рамках показывается последняя в порядке
pipeline (сверху вниз / слева направо), в счётчики попадают все. Пустой OCR отображается как
«Не прочитан». После потери сигнала последний результат остаётся с временем обнаружения.

Счётчики отдельные для каждого запуска процесса/камеры:
- detections: одна рамка после штатного детектора на одном обработанном кадре;
- ocr_readings: readable=True и непустой OCR, включая неопределённые символы;
- complete_readings / partial_readings: сырой текст без # / с #; это не статусы трекера;
- число кадров, треков и уникальных автомобилей этими счётчиками не измеряется;
- correct=null, evaluated=0, accuracy_percent=null: нет эталонной разметки для сопоставления.

CONFIRMED и confidence не используются как Ground Truth. Старый выборочный аудит других видео
не является разметкой этого клипа. Формулировка «Точность не оценена» намеренно сохраняется.

Данные доступны в существующем GET /live/status?camera=Front (или Back), поле readings.
Crop передаётся как ограниченный JPEG data URI вместе с OCR того же исходного кадра.
Временный JSON рядом с файлом превью — вспомогательные данные, не новая БД.
Счётчики передаются не чаще двух раз в секунду и окончательно сохраняются при штатной остановке.
GET /live/system — CPU/RAM хоста API и загрузка GPU 0 через nvidia-smi. Интервал 1,5 с;
запрос к nvidia-smi ограничен 1 с и выполняется в фоновом потоке. Это загрузка всей системы,
не только ANPR. На Linux/WSL RAM/CPU относятся к среде API; первый CPU-замер и отсутствующее
оборудование дают null / «н/д». ANPR/Capture/Browser FPS остаются раздельными для каждого окна.

## Запуск

PowerShell (API, существующая Windows-установка):
```powershell
cd C:\Users\User\Documents\rover-anpr
& "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe" -m uvicorn api:app --host 0.0.0.0 --port 8000
```

Для RTSP в двух отдельных терминалах Ubuntu/WSL используйте существующий launcher:
```bash
cd /mnt/c/Users/User/Documents/rover-anpr
/home/user/.venvs/rover-anpr-cu128-test-20261117/bin/python run_rtsp_camera.py Front
```
Второй терминал — такая же команда с Back. Существующая конфигурация доступа не меняется.

Для видео используйте существующий process_video.py (останавливайте процесс выбранной камеры,
чтобы два процесса не перезаписывали один preview). В терминале WSL:
```bash
cd /mnt/c/Users/User/Documents/rover-anpr
/home/user/.venvs/rover-anpr-cu128-test-20261117/bin/python process_video.py --input results/live_demo_2026-11-16/input_excerpt.mp4 --output results/manual_live_video_check --device cuda --live --preview-path captures/.live-preview-Front
```
Выходная папка должна быть новой: CLI намеренно отказывается перезаписывать результаты.
Для Back замените суффикс preview-пути. Видео обрабатывается настолько быстро, насколько
позволяет ANPR, без имитации исходных 20 FPS. EOF завершает preview; последний crop и счётчики
остаются доступны. --api-url не нужен для визуальной проверки и здесь не задаётся, чтобы тестовое
видео не добавляло события в существующую БД. VIDEO_SOURCE в camera.py также принимает путь
к файлу, но для конечного видео рекомендуем существующий CLI с корректной обработкой EOF.

Проверка: /live, /live/status?camera=Front, /live/system.
