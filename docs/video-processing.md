# Последовательная обработка записей робота

`process_video.py` использует `PlatePipeline` и настоящий worker из
`camera.main`, включая существующий трекинг и подтверждение. `VideoReplay`
наследует handshake `wait_frame`/`fail_worker` из `evaluate_videos.FileReplay`.
Следующий кадр читается только после обработки предыдущего. Потоковый
`VideoStream` и устаревшие результаты live-preview не используются.
Алгоритм подтверждения и рабочие пороги не изменены.

## Запуск

Требуются установленные зависимости проекта, OpenCV с декодером источника
и MP4-энкодером `mp4v`, а также:

- `checkpoints/plate_detector.pt`;
- `checkpoints/plate_recognizer.pt`.

Пути определены в `StandConfig`; размеры, SHA256 и разрешённый источник
весов описаны в `download_models.py`. CLI ничего не скачивает и не
устанавливает. API, Docker, SQLite и RTSP для обработки не нужны.
События подтверждения сохраняются локально без сетевой отправки.

```bash
# Все MP4/MOV во всех вложенных каталогах (регистр расширения не важен).
python process_video.py --input test_videos --output results --device cpu

# Только один файл; квадратные скобки не интерпретируются как шаблон.
python process_video.py --input 'test_videos/Front/12.30.00-12.33.00[R][0@0][0]_ch1.mp4' --output results-single

# CUDA выбирается явно; автоматического перехода на CPU нет.
python process_video.py --input test_videos --output results-cuda --device cuda

# Метаданные и декодирование первого кадра без моделей.
python process_video.py --input test_videos --output probe-results --probe-only
```

При проверке в каталоге обнаружено **шесть**, а не пять файлов: есть
дополнительный `Front/12.36.00-12.39.00[R][0@0][0]_ch1.mp4`.
Для обработки ровно пяти файлов из задания одной командой:

```bash
python process_video.py --input test_videos --output results --exclude 'Front/12.36.00-12.39.00[R][0@0][0]_ch1.mp4'
```

`--exclude` принимает буквальный путь относительно входного каталога,
может повторяться. Исходные записи открываются только на чтение.

## Результаты

Для входного `test_videos/Front/name.mp4` создаются:

```text
results/
  summary.json
  Front/
    name.mp4/
      annotated.mp4
      report.json
      detections.csv
      processing.log
      visibility.csv
      captures/
```

Имя `visibility.csv` задаёт существующий replay-контур `camera.py`.
Вложенность и расширение входного
имени сохраняются в имени каталога, чтобы `name.mp4` и `name.mov` не
конфликтовали. Существующие каталоги результатов не перезаписываются.
Выходной каталог для пакетного запуска должен находиться вне входного.
`results/` исключён из Git и Docker build context; иные имена каталогов
результатов также не следует добавлять в Git.

JSON содержит характеристики источника, число обработанных кадров,
покадровые времена, детекции, чтения, подтверждения, confidence и метрики
обработки. CSV содержит строку на детекцию с номером кадра, временем,
координатами, текстом, confidence, состоянием и ID трека, если он есть.
Для пустых детекций CSV содержит только заголовок. В `summary.json` —
отдельная запись на каждый файл, включая неудачные обработки.

Количество детекций — число наблюдений рамок на кадрах, не число машин.
`unique_vehicle_count` оставлен `null`: надёжной оценки уникальных
автомобилей этот pipeline не предоставляет. Список подтверждённых номеров
также не является подсчётом автомобилей.

Состояния на видео: `detected`, `read`, `confirmed`. Видимый текст — OCR
текущего кадра. Ранее подтверждённый номер не подставляется вместо
несовпадающего текущего чтения. Текущие ограничения гражданского формата
и порога OCR из `camera.py` сохраняются: это изменение не добавляет
восстановление скрытых символов или новые форматы подтверждения.

## Временная шкала и надёжность записи

Метаданные берутся из таблиц `stts/mdhd` MP4/MOV существующим `mov_timing`.
Декодированные размеры берутся из первого кадра. При обработке проверяется
полное число кадров; преждевременный EOF не считается успехом.
Контейнеры без обычной таблицы кадров (например, некоторые fragmented MP4)
не поддерживаются этим parser и требуют отдельной поддержки.

Относительное время каждого исходного кадра берётся из OpenCV PTS;
начальное смещение сохраняется как `decoder_pts_origin_s`. Для VFR
отсутствующие или не возрастающие PTS приводят к ошибке, а не замене
средним FPS. Для CFR предусмотрен fallback по индексу кадра.

Экспорт — **CFR**, частота равна среднему FPS источника. На равномерной
сетке времени удерживается предшествующий исходный кадр вместе с его
собственной разметкой. При этом некоторые кадры дублируются или не попадают
в экспорт, но **каждый исходный кадр обрабатывается ANPR** и отражён в JSON.
Таким образом сохраняется общая временная шкала без ускорения/замедления;
допуск длительности — половина выходного кадра плюс 2 мс округления
контейнера. Исходное разрешение сохраняется. Аудио не переносится.
Сложные монтажные edit lists отдельно не интерпретируются; некорректная
или несогласованная временная шкала завершается ошибкой.

Сначала создаётся `annotated.partial.mp4`. После закрытия writer файл
полностью декодируется повторно: проверяются количество кадров, размеры
и контейнерная длительность. Только после проверки и сохранения отчётов
он переименовывается в `annotated.mp4`. При ошибке/обработанном прерывании
временный MP4 удаляется, отчёт получает `status=failed`. Ошибка одного файла
не мешает остальным, код завершения CLI — 1. Прерывание останавливает
пакет, код — 130. Успех — 0. Аварийное завершение ОС может оставить файл
с явным суффиксом `.partial.mp4`, который не является готовым результатом.

В текущем Python 3.12 отсутствуют cv2, numpy, torch, ultralytics, pytest,
ruff; локальные веса отсутствуют. Попытка CLI остановилась до обработки
с сообщением `Missing dependency: No module named 'cv2'`. Декодирование,
реальные MP4-экспорт и инференс не проверены. Детекции, OCR, ложные чтения,
визуальное качество и совпадение реальных длительностей не оценивались.
Никакие зависимости или модели при работе не устанавливались.

Тесты с моками проверяют CLI, рекурсию, Front/Back, буквальные имена,
EOF, число кадров, соответствие разметки кадру, VFR→CFR, JSON/CSV,
пустые детекции, ошибку кодека и прерывание. Отдельный интеграционный тест
`tests/check_process_video.py` проверяет настоящий camera-worker и MP4
на синтетических кадрах без моделей; автоматически пропускается без runtime.

```bash
python -B -m unittest discover -s tests -p 'test_process_video.py' -v
```

Доступный набор existing/new unittest: 50 passed, 7 skipped (57 всего).
Полный discovery дополнительно не может импортировать
`test_download_models.py`, поскольку отсутствует pytest. Ruff не запускался.
`git diff --check` прошёл. Реальные записи остались неизменными.
