# Форматы и частичные чтения: проверенный объём поддержки

Правила формата находятся в `plate_formats.py` без зависимости от Torch.
`ocr_model/utils/alphabet.py` переэкспортирует прежние имена, сохраняя
алфавит, порядок классов/подтипов и размеры тензоров checkpoint.
`plate_validator.is_valid_plate(text, subtype)` использует ту же проверку.
Одноаргументный вызов сохранён для старых клиентов: только полный type1.
Camera и диагностика всегда передают определённый OCR подтип.

## Проверенные программные пути

| Подтип | Назначение | Синтетические примеры в тестах |
|---|---|---|
| type1 | Обычный однострочный гражданский | A123BC77, A123BC777 |
| type1a | Двухстрочный гражданский | A123BC77, A123BC777 |
| type1b | Жёлтый знак такси/лицензируемых перевозок | AB12377 |
| type5 | Военный автомобильный | 1234AB77 |

Обозначения сопоставлены с разделом 3 ГОСТ Р 50577-2018:
[карточка Росстандарта](https://protect.gost.ru/gost/details/86504e75-dbfe-47fa-b298-1a7b69d1a4b7),
[текст стандарта](https://base.garant.ru/72098366/).

Для каждого примера `test_verified_types_from_ocr_tensors_to_http_and_history`
пропускает синтетические выходные тензоры OCR через настоящий `_read()`
PlatePipeline, Camera, EventSender, FastAPI/Uvicorn и SQLite. Для type1a
используется более квадратная вырезка и соответствующий OCR bucket.
Проверяются текст, subtype, CONFIRMED и история. Ни YOLO, ни веса OCR
в тестах не запускаются. Детектор и нейросетевой predictor подставлены.

Это подтверждает программную совместимость полного пути, а не качество
обнаружения/чтения фотографий. Цвет, реальная двухстрочная вёрстка, точность
классификации подтипов и соответствие всем требованиям ГОСТ не измерены.
Остальные перечисленные в OCR подтипы используют общие шаблоны, но отдельной
сквозной проверки здесь не имеют и не заявляются проверенно поддержанными.
Таблицы действующих регионов/ведомственных кодов тоже не проверяются.

## Неизвестные символы и доказательства

`observation()` сохраняет `#`. Если вероятность символа ниже 0.85, он тоже
становится `#`; низкая вероятность подтипа не допускает смешивания типов.
Известные кириллические гомоглифы нормализуются в алфавит OCR, пробелы и
перенос строки удаляются. Это нормализация записи, не восстановление букв.

`resolve()` использует максимум десять наблюдений разных frame_id одного
пространственного трека. Символы объединяются только в группе одинакового
подтипа и длины. Для каждой позиции сохраняются supporting frame_ids.
`#` не даёт голосов ни за один символ. Любое достоверное противоречие в
текущем окне оставляет эту позицию неизвестной, без выбора по шаблону.

- **PARTIAL**: остаётся хотя бы один неизвестный/конфликтующий символ.
- **PENDING**: все позиции прочитаны, но повторных доказательств ещё мало.
- **CONFIRMED**: каждая позиция полного валидного номера имеет минимум три
  независимых кадра подтверждения, без конфликта в окне.

Например, три `A123##77` и три `####BC77` могут подтвердить A123BC77:
каждый символ действительно есть минимум в трёх OCR-наблюдениях.
Повторение только `A123##77` никогда не восстановит BC. Одного полного
чтения после частичных недостаточно для подтверждения недостающих позиций.

Для смены ранее подтверждённой идентичности требуется минимум семь кадров
на символ в окне истории. Поскольку конфликты не подавляются большинством,
смена может потребовать полного выхода старых наблюдений из окна (до десяти
новых кадров). Это сознательно консервативнее старого голосования строк.
Старый confirmed_number не подставляется в противоречащее текущее чтение.

Частичный текст не используется для текстовой повторной идентификации
после потери объекта. Пространственное сопоставление не смешивает разные
subtype. Смена подтипа может создать новый трек. Идентичность автомобилей
при пересечениях по-прежнему ограничена простым трекером центров.

В API-событии `plate` — накопленный результат, `observed_plate` — текущее
чтение после маскирования ненадёжных символов, `character_evidence` —
поддерживающие кадры. Полные неподтверждённые PENDING-чтения показываются
в диагностике/превью, но пока не отправляются в историю. PARTIAL и
CONFIRMED отправляются с явным status и subtype.

Оценка уверенности остаётся агрегатом исходных OCR confidence, не
измеренной вероятностью правильности номера. Уверенную повторяющуюся
ошибку самого OCR этот механизм не гарантирует выявить: независимого
детектора физического перекрытия символов нет.

## API, миграция и совместимость

По умолчанию `/plates` и `/history` возвращают только CONFIRMED, как раньше.
Для частичных результатов: `/plates?include_partial=true` и
`/history?include_partial=true`. Новые поля добавлены без удаления старых.
Старые события без subtype/status принимаются как прежние подтверждённые
события. Нельзя прислать `#` с CONFIRMED даже через старый контракт.

`database.init_db()` добавляет subtype (nullable) и status (default
CONFIRMED) в существующую detections, сохраняя старые id/записи. Старым
строкам не придумывается subtype. Обновления PARTIAL→CONFIRMED меняют ту же
строку трека, даже без улучшения quality. event_id-дедупликация и ключ
session_id/track_id сохранены.

SQLite хранит последнее состояние трека, а не все смены его чтений.
История может стать PARTIAL при потере доказательств и исчезнуть из старого
фильтра; полностью журналировать изменения — отдельная доработка.
Покадровые JSON/CSV офлайн-режима содержат промежуточную диагностику.

## Запуск тестов без моделей

```bash
PYTHONPATH=tests python -B -m unittest test_plate_evidence -v
# В окружении с уже установленными API + Camera зависимостями:
PYTHONPATH=tests python -B -m unittest test_plate_formats_http.FormatsHttpTest -v
```

Проверены также миграция старой SQLite, повторные event_id, API нескольких
треков и координаты. Во время реализации использовались существующие
окружения Camera и временное API-окружение предыдущего этапа; новых
зависимостей/моделей не скачивалось. Реальные видео не обрабатывались.

Проверенный регрессионный набор: 102 теста, 101 прошёл; один тест команд
с подставным Compose пропущен из-за отсутствия GNU Make. Проверки pytest
загрузчика моделей и Ruff не запускались (эти пакеты не установлены).
