# Rover ANPR: локальная двухкамерная VIDEO DEMO

Запуск Windows:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\User\Documents\rover-anpr\start_video_demo.ps1"
```
Страница: http://localhost:8000/live. Повторная команда открывает уже работающую демонстрацию.
Используются существующие Windows Python 3.13 (API) и WSL CUDA-окружение
/home/user/.venvs/rover-anpr-cu128-test-20261117/bin/python. Ничего устанавливать не требуется.

1. В окнах Front и Back выбрать отдельные файлы из test_videos.
2. Start Both начинает общую пару; Pause Both приостанавливает оба потока; Start Both продолжает.
3. Restart Both начинает два новых прогона, очищая карточки, треки и статистику.
4. Отдельные Start/Pause/Restart камер сохраняются, но выводят пару из общего таймлайна.
5. После EOF последний кадр остаётся видимым. Новый Start Both после EOF начинает пару заново.

Источники читаются последовательно по PTS. В общем режиме первый старт ждёт готовности обоих
worker, продвижение привязано к завершённым PTS соседа с допуском по периодам источников.
Счётчики кадров для выравнивания не используются: FPS/число кадров у файлов различаются.
Кадры ради синхронизации не пропускаются. Если ANPR медленнее исходника, воспроизведение
замедляется, lag растёт; интерфейс показывает фактический темп. Это не заранее рассчитанное видео.

Видео имеют фиксированные блоки с сохранением пропорций. Под каждым — карточки всех текущих
детекций с реальным crop. Карточки обновляются по track_id; после исчезновения сереют и остаются
до 5 с с пометкой «Последнее», не считаясь текущими. Затем удаляются. Область карточек фиксирована
и прокручивается при большом количестве объектов. Кадр/crops/рамки передаются одним пакетом.

Основные метрики: CPU/GPU/RAM всей системы API; отдельные ANPR/Browser FPS; детекции на кадрах,
непустые OCR и подтверждённые события треков. Это разные величины. CONFIRMED — статус алгоритма,
не Ground Truth. Без эталонов точность не оценена. Подробные тайминги — в «Диагностика» и API.

Существующие endpoints сохранены. Новый POST /live/demo/both принимает action start/pause/restart
и videos {Front: id, Back: id}. Данные управления — в игнорируемой .run/video-demo, новая БД не нужна.
Демо не отправляет тестовые события в прежнюю историю /plates. .env, адреса камер и веса не меняются.
Без VIDEO_DEMO_ENABLED=1 остаётся обычный RTSP-режим; скрипт включает флаг только для процесса API.

Известное ограничение: YOLO может принимать пульт за номер. Проверенные простые пороги
confidence/aspect убирают также реальные номера, поэтому небезопасная фильтрация не включена.
